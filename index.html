      PROJECT / 02 · ——

      StudySyncEngine

      Local automation / academic workspace utility

      PROBLEM
      Reduce study-file clutter and repeated manual organisation without requiring a cloud runtime.
      SYSTEM
      Filesystem events flow through scanning, OCR, rules, a pub/sub broker, local statistics and a lightweight focus controller.
      STACK
      Python · Tkinter · Watchdog · OCR · local processing
      KNOWN LIMITS
      OCR depends on image quality, the project is Windows-oriented, and large batch scans may slow the interface.
      Inspect architecture + source map
      STUDYSYNC / SOURCE-MAPPED WORKFLOWPUBLIC REPOSITORY · MAY 2026
      Filesystem watchsrc/watcher.py → Scan / OCRsrc/scanner.py → Event brokersrc/broker.py → Classify + movesrc/engine.py → Desktop UIsrc/gui.py
      OPTIONAL WINDOWS FOCUS PATHsrc/focus.py ↗

      The public repository currently contains no committed screenshot assets. The workflow above is mapped to inspectable source files rather than reconstructed as a synthetic UI screenshot.

      DECISIONTkinter keeps the desktop utility lightweight; Watchdog reacts to filesystem events; a pub/sub broker was introduced after direct UI updates caused freezes during larger scans.

      LIMITSOCR accuracy depends on image quality, the current build is Windows-oriented, and large batch scans can temporarily slow the interface.

      NEXTThe repository lists semantic classification, cloud synchronisation, cross-device persistence and improved handwritten-note OCR as future work.
